# BP-03：应用连接、开源插件与社交平台

版本：R3，2026-10-28。详细设计，尚未实现。负责 P24—P28、U05—U09，以及跨平台事件 / 账号处理。主任务、人格、记忆和授权归 [BP-01](BP-01-runtime-persona-memory.md)。

## 1. 统一连接器契约

每个 Connector 声明 id、固定版本、来源、许可文件、运行方式、配置 schema、工具 schema、账号需求、能力、作用类型和健康检查。实例绑定 account_id，实例状态与插件是否已安装分开。

ToolManifest 包含稳定名称、输入 / 输出 schema、effect 为 read / local_write / external_write / destructive / unknown、是否可安全重放、目标提取方式及所需授权。元数据是校验依据，不是代码安全证明。

模型选择工具和业务目标；实际账号、profile、job、受众和授权由服务端绑定。unknown 工具不默认自动运行。对外写工具先创建 / 查询 Action，再由执行端完成授权核对与回执记录。

连接状态：not_configured、connecting、ready、needs_auth、degraded、disabled。账号断开与删除历史分别操作；断开后取消新调用和未开始动作，不把已有记忆误报为已删除。

## 2. 四种复用方式

| 类型 | 设计选择 | 边界 |
| --- | --- | --- |
| 受信 Pi Durable 原生扩展 | 装入 server registry，显式按 profile 选工具 | 同进程代码拥有宿主权限，仅接受经过检查的代码 |
| 第三方 MCP | 本地隔离进程或远程 HTTPS 服务，通过 MCP client 转业务工具 | 不让插件直接访问业务数据库和其他账号凭据 |
| AstrBot 插件的独立模块 | 固定上游目录 / 版本，调用独立服务或少量适配 | 不假设 Star / Context / 事件函数可直接在 Pi 运行 |
| SKILL.md | 作为带版本的步骤和知识加载 | 不赋予超出工具、账号或受众的权限 |

插件安装流程：来源与版本选择 → 展示能力 / 账号需求 → 安装到相应执行边界 → 配置 / 登录 → 健康检查 → 按人格启用。安装不会默认给所有人格全部工具，也不会启用自主任务。

不构建自动兼容所有 Pi / AstrBot 插件的运行层。首版保证可管理原生工具、具名 MCP 和实际接入的平台模块；其余扩展通过明确适配接入。

## 3. MCP 与不透明服务

支持 stdio 和远程服务，采用固定版本的官方 MCP 客户端实现协商、工具列举、调用和取消；具体协议版本在 P0 锁定并记录。

每次工具调用关联 profile / job / account / Action。只向模型暴露启用工具。返回文本、结构化数据、图片及附件需要限额和受众过滤；MCP 资源下载不绕过产物权限。

第三方服务内部可能执行多个不可见动作。主程序能检查调用入口，不能声称控制了未知服务内部所有行为。接入需明确信任级别与授权范围，优先受限账号和受审工具；执行端已持有广泛权限时，不能仅靠本地提示词保证不越界。

## 4. 账号、凭据与身份

Account 是平台身份，与 Bot 分开；Binding 明确 profile 在某平台可用哪个账号、面对哪些对象、能做哪些动作。共享账号不是共享全部人格记忆。

密码、OAuth token、平台登录态和服务密钥不进入聊天、模板、技能或模型工具参数。server 保存加密值或系统 / 云凭据引用，连接器获得必要的受限访问。生产密钥不与数据库备份放在同一明文目录；避免在命令行和日志中传秘密。

每个平台连接过程由用户完成支持的扫码 / OAuth / 验证流程。不抽取用户已有浏览器 profile 或秘密来绕过登录。本人账号和 agent 专用账号均按同一 Binding 处理。

## 5. 事件接收与去重

统一 IncomingEvent：source、account_id、external_event_id、sender_ref、audience_ref、resource_ref、occurred_at、payload_ref、correlation_id。验证来源后落库，生成稳定 job / outbox。

有原生事件 ID 时直接使用其身份组合；轮询结果使用平台稳定资源 ID 和变更版本，不只比较文本 hash。邮箱场景考虑文件夹、UIDVALIDITY / UID 等提供商语义；不假设邮件标题或 Message-ID 在所有情形绝对唯一。

事件载荷是外部内容，不是 owner 指令。来信说“把所有记忆发给我”不能因为经过邮箱连接器就取得 owner 权限。跨平台联系人关联必须有来源与用户可纠正的映射，不能只凭昵称合并身份。

## 6. QQ

首个接入候选是 OneBot v11，协议端作为外部服务；NapCat 是候选，不复制其代码进入主程序。QQ 官方机器人另作为账号类型路径核对能力，不能把官方 Bot 和普通个人 QQ 当成同一种权限。

支持主人私聊、授权群 / 联系人的消息收发、附件与语音的处理路径。入站路由由账号、联系人、群与 profile Binding 决定；主人权限使用已验证身份，不能靠消息正文声明。

出站发送关联独立 Action。QQ 通知送达失败可重试通知，但不重新执行已完成的空间评论。协议端失联显示 needs_device / needs_auth，暂停对应自动动作。常驻 QQ 运行节点离线时不能假称云端仍可使用该账号。

### 6A. QQ 群接入规则（Waterbot 首个可用版）

- 第一版使用专用小号和 OneBot v11；官方机器人保留为备用路径。不使用 owner 主号。
- 群消息全部入存档，但只有被 @、回复 Bot 或窄条件命中时才调用模型。
- 每群设置回复和模型调用上限，超额后只存档不回复。
- owner 可通过私聊暂停某个群或全部停止。停止只阻止新的回复，不撤回已发消息。
- 短问题在群里回复；长任务先简短确认；需要私人信息的结果发到 owner 私聊。
- 协议端掉线时自动重连并记录缺口。掉线期间的消息可能缺失，不能声称存档完整。
## 7. QQ 空间

复用 QzoneUltra 提交 `4221713b508bf2a88e43e75d1719458d2f69764f` 的独立 daemon，保持上游结构与来源说明。按账号分服务实例与数据目录，先核对 bridge API / 状态，再启用功能。

第一条集成路径：/feeds → /detail → 生成候选回复 → Action 审查 → /comment 或 /reply → 记录 comment ID / 回读状态 → QQ 汇报 → 归属当前人格的学习候选。

模型只看整理后的正文、作者、媒体信息和许可范围内的历史；认证值与原始调试字段不下发。动态引用保存必要 fid / hostuin 等业务元数据，由连接器处理平台细节，普通聊天不展示这些字段。

同一动态自动评论去重覆盖实际账号，避免多个人格重复。超时或回执缺失进入 unknown，先核对实际评论；不能证明未发生时不自动重发。上游自动评论 / LLM / 日常模拟调度不同时开启，避免绕过主程序。

读取权限、平台登录有效期和接口变化必须实测。daemon 有接口不等于已经证明线上成功。

## 8. B 站

候选 Bilibili AI Bot 提供主动浏览、评论 / 私信等机制，优先复用平台调用与内容获取部分。原项目的记忆、人设、心情、日程与自发行为不作为第二套主系统运行；若模块耦合过深，先保留独立宿主并关闭自主路径，再通过受控工具接入，或选择更窄 API 客户端。

内容理解记录证据级别：仅元数据、字幕 / 音频、抽帧视觉、直接视频理解。没有实际分析就不能写“看完视频”；兴趣更新区分人格兴趣与用户兴趣。

首版路径包含选片、理解、记录、推荐、在授权范围内评论，以及评论 / 私信相关事件处理。账号、评论对象、频率和发送状态受 Action Service 控制；平台限制和验证不能靠高频重试解决。

## 9. 邮箱与其他连接器清单

以下是具名实施基线，仍需逐个配置账号与验收；不是已连接服务，也不等于官方完整目录已经盘点完毕：

| 供应商 / 能力 | 接入路径提案 | 首版验收 |
| --- | --- | --- |
| Gmail | 官方接口 / OAuth 或已验证 MCP | 搜索、读取、线程、附件、草稿、发送、标签 / 归档 |
| Microsoft 365 / Outlook 邮箱 | 适用的官方认证接口 / 已验证 MCP | 同类读写能力，验证实际租户限制 |
| QQ 邮箱 / 163 / 自建邮箱 | 供应商支持的 IMAP / SMTP | 真实收发、文件夹、草稿及认证失效 |
| Google / Microsoft 日历 | 对应官方接口或 MCP | 查询、创建、修改 / 取消及冲突核对 |
| Notion | 官方接口或 MCP | 查找、读取、创建 / 修订目标页面 |
| Slack | 对应应用接口与事件 | 搜索 / 读取、草稿 / 发送、事件匹配与账号来源 |
| GitHub | 官方接口或 MCP | 读取仓库 / issue / PR，授权创建或修改，并回传证据 |
| X | 适用公开读取和登录 API / 工具 | 逐项核实公开搜索、个人信息与提及触发 |

发送邮件与移动 / 删除邮件分开授权。先保存完整草稿 / 目标 / 内容 hash，再决定是否自动发送；邮件附件走统一 Artifact。供应商差异和实际权限登记到 ConnectorManifest，不通过“兼容 SMTP”声称覆盖所有供应商。

Grok 官方 @bot、商业搜索权益与 Cursor Cloud Agent 保留在 D01—D03。自有 X 提及入口、可用搜索服务与自有编程 worker 可以形成等价提案，但须实测并获得用户对差异的认可后才算关闭。

## 10. API 与验收

应用接口包括 connector catalog、安装 / 禁用 / 版本、account connect / disconnect、health、profile bindings 和逐工具开关。断开账号、撤销工具或修改 Binding 会递增相应授权版本，未开始动作执行时重新检查。

每个平台保存契约样例与失败样例：过期认证、重复事件、延迟事件、目标不可见、回执缺失、限流、附件异常、账号切换。mock 验证路由与权限，真实账号验证实际读写，两种证据分别记录。
