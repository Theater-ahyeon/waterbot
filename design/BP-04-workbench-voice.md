# BP-04：跨端工作台、实时语音与用户交互

版本：R3，2026-10-28。详细设计，尚未实现。负责 P01—P15 的界面、P42—P52，以及记忆 / 账号 / 自动化管理体验。以 [BP-01](BP-01-runtime-persona-memory.md) 的服务端身份和状态为权威。

## 1. 技术与承载面

主客户端采用 React + TypeScript + Vite，基础交互复用 shadcn/ui / Radix 和 Tailwind 语义主题。具体兼容版本在项目创建时固定；本轮不安装任何依赖。服务端状态通过 API 与 SSE 同步，客户端不维护第二套任务或审批事实。

桌面与手机优先共用响应式 Web / PWA。系统分享、后台推送、本机命令、硬件钥匙等若需要原生桥接，则对应功能明确增加受信桥接并真机验证；PWA 可打开不算所有原生能力已经实现。全部原生平台安装包不是用户已确认要求，个人跨端能力仍必须覆盖。

## 2. 信息架构

| 入口 | 内容 | 核心动作 |
| --- | --- | --- |
| 对话 | Bot / 人格、群聊、置顶和分组 | 切换、创建、@、语音、附件、改向与停止 |
| 活动 | 运行任务、待审、需输入、例行任务 | 看真实进度、决定、暂停和查看历史 |
| 记忆与成长 | 事实、偏好、经历、共享及变更 | 搜索、纠正、批量共享 / 撤回、检查依据 |
| 工具与连接 | 应用、账号、技能、电脑与本机设备 | 安装 / 连接 / 断开、权限和健康状态 |
| 资料库 | 文件、Pages、模板和分享 | 预览、修订、下载、发布副本 / 取消分享 |
| 设置 | 模型、通知、时区、用量、数据与更新 | 保存个人规则和设备设置 |

桌面使用可收起的 Bot 侧栏、主对话和右侧检查面板。手机将检查面板变成独立页面 / 抽屉，不挤成三列。当前人格、实际账号和工作位置在需要决定的地方显示；底层协议字段放诊断页。

## 3. 对话与多 Bot

消息支持文本、引用、附件、工具 / 电脑活动、产物、问题表单、审批、草稿和语音卡片。每个卡片来自服务器记录，pending、failed、unknown 与 confirmed 不能只靠颜色区分。

编辑中的文字按会话保存，切人格不丢草稿、不把草稿送到另一个 Bot。发送后显示明确作业状态；网络重试沿用 client_request_id。追加消息可选改变当前工作或排队，常规对话由服务端路由到控制会话。

群聊支持成员管理、显式 @、消息回复与可见交接。表态用于轻量反馈，不能单独代替有账号 / 目标 / 内容约束的正式批准。审批与秘密输入在私有处理面完成，不把敏感输入广播给群中每个 Bot。

停止按钮分当前回答、指定任务和人格自主活动；全局暂停另提供明确入口。停止后依然显示已完成动作和待核对结果，不伪造“所有操作已撤回”。

## 4. 记忆管理的具体操作

默认按当前人格筛选，用户可切“全部人格”做管理，模型权限不因此扩大。每张记忆卡显示：正文、类型、来源 / 时间、明确或推测、有效状态、可见人格、允许受众和最近变更。

交互流程：勾选一条或多条 → 分享给 → 选择人格 → 立即显示共享结果。普通共享使用持续引用；独立复制和对外分享摘要分别作为清晰命名的动作。

取消共享时展示实际影响范围：哪些人格失去访问、哪些摘要 / 活动作废、哪些公开或独立副本不会被收回。用户能查看操作结果及失败项，不只看到一个开关已关闭。

纠正可直接编辑事实 / 偏好并补一句原因，服务器创建新版本。冲突信息并排呈现来源；“最近总熬夜”与“喜欢熬夜”必须能保持为不同判断。人格自身兴趣、对用户的认识和程序经验分别筛选。

成长时间线展示发生过的变化及依据，例如“你纠正了回复风格”“根据新信息撤销旧偏好”。不显示虚构等级、意识或情感真实性分数。自动重大人格变更以可比较、可回滚提案呈现。

## 5. 审批、草稿与长期规则

待审卡包含：发起人格、账号、目标、实际拟发内容或操作、来源、需决定原因和有效状态。用户可允许一次、拒绝、修改后重审，或将匹配范围保存为长期规则。

长期规则界面结构化显示人格 / 平台 / 账号 / 对象 / 动作 / 频率，另允许自然语言描述；保存前回读解析出的范围，不把含糊指令变成自动允许全部。

已有规则内自动执行，不反复弹确认。过期或内容版本不匹配时按钮失效并解释具体变化。多设备同时审批依赖 expected_revision 保证只接受一个有效决定。

邮箱和其他外发草稿支持改收件人、正文与附件；保存改动后形成新的 payload hash。规则与用户的一次批准不能偷偷适用于修改后的其他目标。

## 6. 电脑、文件与 Pages

电脑面板显示连接状态、实际空间、当前控制者和工作画面。人工接管后在手机与桌面都清楚显示“由你控制”，交还按钮需要真实控制权变更回执。

文件卡显示版本、生成任务、格式、预览 / 下载状态及来源。生成中、渲染失败、文件不存在与下载无权限分别处理。点击“继续修改”关联现有产物，不默认另造不相关文件。

Pages 在隔离渲染器显示图表 / 表格 / 跟踪器，可与 Bot 讨论修订并绑定例行任务。公开分享使用发布副本；工作台会话凭据不能出现在 iframe 或链接中。

## 7. 语音架构

复用 LiveKit 类实时传输和 STT / TTS 组件。语音处理层负责音频、转写、回声 / 轮次与播放，不运行第二套长期人格或独立任务循环。

| 模式 | 流程 |
| --- | --- |
| 听写 | 麦克风 → 转写 → 可编辑输入框 → 用户发送 |
| 语音留言 | 录音 / 生成音频 → 对应转写 → 播放 / 暂停 |
| 实时交流 | 实时音频 → 确认后的用户轮次 → 当前 Bot 控制会话 → 流式文字 / 语音输出 |

用户说话时可中断当前 TTS 播放；是否取消工作任务由表达含义及明确控制决定，不能把“先别说了”误当全局停止。任务持续执行时，控制会话可读取权限范围内的真实进度进行交流。

语音房间和凭据绑定当前 owner / profile / 会话，切人格时结束或重新绑定语音会话，不能把旧人格的后续音频播放进新窗口。丢包、断线、转写失败和权限拒绝提供文字降级；不能伪装正在通话。

目标指标测量首字延迟、打断停止延迟、端到端延迟、识别质量和单次成本，先有实际设备 / 模型证据再制定数值承诺。语音输出不能声称尚未核实的动作已经成功。

## 8. 通知、搜索与跨端状态

通知区分任务完成、需要输入、动作未知和服务故障。用户可按 Bot、渠道与免打扰时段设置；当前已读会话尽量不重复推送。通知只带必要摘要，敏感正文默认不进锁屏。

点击通知进入原 profile / 会话 / job，不用当前选中的人格替代。跨端审批、已读、草稿及任务状态由服务端同步；重复事件按事件 ID 丢弃，SSE 补不齐时先刷新快照。

统一搜索覆盖用户有权管理的消息、Bot、群、文件、记忆、技能与例行任务，结果可定位来源。模型使用搜索时仍受当前 profile 和受众限制，不能复用 owner 的管理视图权限。

## 9. 无障碍与状态验收

复用有焦点管理的 Dialog / Sheet / Menu / Select，输入有标签与错误关联；图标按钮有可访问名称。支持键盘操作、焦点返回、长中文、深浅主题、减少动效和 200% 缩放。

手机测试至少覆盖 360px 窄屏、横竖屏、软键盘、安全区域和触控。审批、停止、分享等操作在窄屏仍清楚可达，不依赖 hover。手机文件 / 分享、推送和硬件桥接按实际系统分别验收。

每个页面明确 loading、empty、offline、permission_denied、version_conflict、error、partial 和 success。乐观界面不能把未确认的外发提前标成成功。
