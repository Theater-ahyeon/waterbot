# BP-05：技能、自动化、自主探索与成长

版本：R3，2026-10-28。详细设计，尚未实现。负责 P29—P35、U03—U04；长期记忆权限、运行和副作用以 [BP-01](BP-01-runtime-persona-memory.md) 为准。

专题证据与比较见 [长期记忆调研](../research/LONG_TERM_MEMORY_RESEARCH.md)。事实提炼、人物理解和程序经验分别处理，不把不同产品的公开分数直接作为本项目选型结果。

## 1. 技能对象与生命周期

Skill 包含 id、owner / sharing_scope、version、name、description、trigger、required_capabilities、inputs、steps、validation、failure_policy、approval_boundaries、source_refs 和 status。来源可以是用户编写、已完成任务、示范或开源包。

状态：draft → tested → enabled → deprecated / disabled。正文是过程知识，不因提到某工具就获得该工具权限。新版本保留差异和回滚路径，运行作业固定调用版本。

创建技能时先根据真实任务生成草稿，再补输入和异常路径，用新样例测试。仅保存成功轨迹会掩盖失败条件；测试结果需关联输入、输出和证据。重复技能先比较已有版本，不自动堆积多个同义条目。

## 2. 示范学习

Teach 模式录制用户明确开始 / 结束的受限交互：页面地址、可见语义目标、操作、前后状态和必要截图。暂停敏感输入期间的截图、DOM 值与事件记录，不录入密码、令牌或验证码。

从示范生成可编辑技能草稿，区分固定步骤和变量输入，标记依赖的账号、网站状态、授权与失败路径。录制不是任意脚本的可信认证。

先在安全样例或不产生外部写入的测试环境验证；确需真实写入时按原授权执行。网站变化、关键选择器失效或账号改变时重新观测 / 测试，不能盲重放一串屏幕坐标。

## 3. 例行任务数据模型

Routine 包含 id、owner_profile_id、revision、instruction、skill_version、trigger、timezone、next_due_at、input_refs、account_bindings、delivery_target、policy_ref、budget、missed_run_policy 和 status。

Trigger 支持一次时间、重复时间、具名事件和 webhook。保存后显示自然语言说明、时区和下次运行，避免用户直接理解内部 Cron 字段。所有时点存 UTC，另存 IANA 时区和原规则。

Occurrence 记录 routine_id、revision、logical_occurrence、trigger_event_id、job_id、状态和结果引用；唯一键阻止同一次调度重复入队。编辑产生新 revision；旧作业保留原指令，但实际发送仍检查现行权限。

## 4. 调度与 Pi 的分工

应用调度器只计算哪次例行任务到期，并在业务 PostgreSQL 事务中创建 Occurrence + dispatch_outbox。真正作业由 Pi 执行和恢复；不引入 Redis 队列或另一套工作流引擎。

单个 host 定时器指向最近到期项；server 启动扫描未处理到期记录。Pi sleepUntil 用于运行中的持久等待与重试延迟，不另启动一套同义周期调度器。

错过运行的默认提案：社交外发 skip；汇总报告 coalesce 为一次；catch_up 只在用户明确选择且有次数上限时启用。夏令时重复时刻默认执行一次，缺失时刻默认跳过该次，并在下次运行说明中显示。部署主机时区不改变用户时区。

事件触发先验证来源，再按具体匹配规则落库；重复投递只产生一次 Occurrence。变更或删除例行任务要区分停止未来触发与取消正在执行作业，UI 分别说明并提供动作。

## 5. 委托与自主探索

Job.origin 区分 user、routine、event、bot_handoff 和 autonomous。用户委托优先；同一人格可以有多个工作主题，但外发账号和桌面冲突资源串行化。

AutonomyPolicy 指定人格、可探索来源、时间窗口、任务类型、反馈目标、外发范围和预算。社交浏览先检查新内容，只有可用候选或明确挂念才请求模型；不为制造“生活感”定时伪造经历。

探索可以服务用户，也可以发展人格兴趣；两种兴趣分别保存。候选内容、选择理由的简要依据、实际获取内容和产生的动作形成 trace，便于以后评估探索策略。

初始并发提案：全局 4 个模型工作、单人格 2 个、同一账号的外发 1 个、同一桌面的 agent 控制者 1 个。它们是可调的资源默认值，不是已验证容量或速度指标。

## 6. 用量与预算

在发起模型 / 付费工具前原子预留 token / 调用额度，完成后按实际 usage 结算并释放余额。用户任务和自主活动分别计账；每日边界按用户时区，服务器重启不清零。

价格来自已配置供应商的版本化价目，缺价格显示未知，不当成免费。现金费用只是估计时明确标注；真正硬性总消费还需供应商侧限额。失败尝试、学习整理、语音和图片 / 视频处理也计入。

超预算停止新增自主调用、显示等待或已暂停，不反复向模型询问是否继续花费。授权预算的变更由用户或已明确规则决定。

## 7. 长期理解和人格成长

学习管线：真实来源 → 候选提取 → 权限与冲突检查 → 分类事实 / 偏好 / 推测 / 程序经验 → 保存版本 → 后续应用 → 接收纠正。

用户明确说“以后这样”可作为当前范围的强证据；单次行为或第三方描述先保存为待证推测。暂时状态有适用时间，不覆盖长期偏好。矛盾结论保留来源，由新证据或用户纠正更新有效版本。

基础人格由用户设置；措辞、兴趣和相处方式可以在证据支持下演变。重要价值、身份或行为范围的改变作为可查看、可回滚提案，不通过自动学习扩大权限。

后台整理只处理新增或变更记录，合并重复、标记失效和保留来源；混合来源摘要继承最严格范围。每个整理任务有输入水位和幂等 ID，重启不会重复新增同一经验。

明确事实 / 纠正走当前事实路径，其他经历可异步整理。人物反思和概览都是可重建视图，保存 observer / subject、来源和处理水位；服务返回了摘要不代表已经学习正确。低频读取可以降权，不自动删除仍有效的重要事实。

若派生记忆服务另行调用 LLM、embedding 或 reranker，相关写入 / 整理 / 查询开销也要进入应用预算，不能只看 Pi 的模型 usage。

## 8. 论文的工程位置

| 参考 | 采用的机制 | 不能声称的结果 |
| --- | --- | --- |
| ReasoningBank | 从成功 / 失败中提炼有适用条件的经验 | 经验被写入不等于已经提高能力 |
| ACE | 增量维护、去重和修订，而非反复全量重写 | 不能保证长期上下文绝不丢失 |
| Harness² | 候选技能 / 指令变化，离线对照执行，再采纳有证据版本 | 模型自评不能证明真实社交效果更好 |
| Dream-RSI | 有评分与历史探索树时，比较探索预算和停止策略 | 普通聊天记录不能模拟未发生的社交分支 |

首版必做的是可验证记忆学习和技能维护。Harness² 式比较可先用于离线草稿与固定案例；Dream-RSI 保留 trace 和可插拔探索策略边界，不在缺少回放条件时声称复现。所有实验沿用相同授权和费用上限。

策略 / 技能候选先进入 sandbox，在已知案例和保留的新案例上比较。评估器不允许真实发送评论或邮件；通过后创建可回滚版本。不能把实时账号作为无限对照试验场。

## 9. 成长评估与验收

维护小而有区分度的中文案例集：明确偏好、临时状态、冲突信息、仅一次的行为、外部转述、跨人格共享、撤回和新的迁移场景。比较开启 / 关闭学习的输出，而非只考背出原句。

LongMemEval 参考时间、跨会话、知识更新与拒答；PersonaMem 参考当前偏好、变化原因及新情境应用；LoCoMo 补长对话；LongMemEval-V2 单独检验网站与工作流经验，不与 v1 当作同一任务分数。新增 / 删除、检索、生成及权限错误分别诊断，统一记录总成本与延迟。

客观项包括正确引用、时效、权限、重复动作和恢复；主观项由用户评价互动是否贴切、人格是否连续、是否过度迎合。二者分开，不生成没有根据的“理解度 95%”。

自动化验收覆盖：时区与夏令时、重复事件、错过运行、日程改版、重启、预算竞争、暂停、输入缺失、技能更新和撤回来源。真实验收至少完成一次示范到技能、一次定时、一次事件触发和一次纠错后跨会话应用。
